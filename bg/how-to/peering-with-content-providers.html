# Peering с доставчици на съдържание

IPFS ви позволява да извличате данни от доставчици чрез CIDs. Този процес обикновено включва търсене в content routing, за да се намерят доставчици за CID в DHT и IPNI.

Ако стартирате IPFS възел, който обслужва много заявки, например публичен HTTP gateway, може да успеете да ускорите заявки чрез поддържане на дълготрайни връзки към възли, които предоставят много CIDs.

Приоритизирането на връзките към определени peers се нарича Peering, и можете да кажете на IPFS кои peers да приоритизира, като редактирате конфигурацията на Peering (opens new window) в конфигурационния файл на Kubo (opens new window).

Например, за да peer-вате с възли от Cloudflare, актуализирайте конфигурацията си, за да включите секция Peering по следния начин:

{
  "Peering": {
    "Peers": [
      {
        "ID": "QmcfgsJsMtx6qJb74akCw1M24X1zFwgGo11h1cuhwQjtJP",
        "Addrs": ["/dnsaddr/node-8.ingress.cloudflare-ipfs.com"]
      }
    ]
  }
}

TIP

Като цяло потребителите, които стартират IPFS у дома, няма да им трябва да настройват peering и могат да игнорират тази страница!

Peering е най-полезен за възли, които имат много едновременни връзки, защото предотвратява connection manager (opens new window) да отхвърля връзки, които смята, че вече не са „полезни“. Ако се окажете, че работите близо до лимита на connection manager-а, може да имате полза от peering с доставчици на съдържание.
